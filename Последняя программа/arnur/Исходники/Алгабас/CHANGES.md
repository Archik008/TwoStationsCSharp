Номер версии оставляет место этапам 4 и 7 (этап 4 — АКЖТ 5.3 / Алгабас 2.4, этап 7 — 5.6 / 2.7), которые делаются отдельно.

| Что | Как сделано | Файлы |
|---|---|---|
| Как переводится | Как gettext: в коде строки остаются **русскими** — это ключи. Словари `Lang/Strings.kk.json`, `Lang/Strings.en.json` вшиты в exe (`EmbeddedResource`, `WithCulture="false"` — иначе MSBuild принимает `.kk.` за культуру и уносит словарь в отдельную папку). Перевод — `L.T(текст)`: точное совпадение → шаблон с дырками `{0}` (как в `$"Поезд №{t.Number} ушёл"`; содержимое дырок переводится тоже, в переводе их можно переставлять) → приставки «08:01:05  », «[Занятие] » → многострочный текст → составной по «: », « — », «. », «, » → известные куски. Шаблон не берётся, если его дырку удалось перевести только кусками (иначе «Поезд №{0}» съедал бы любое сообщение о поезде) | `Core/Lang.cs` (новый, общий и для «Преподавателя») |
| Окна переводятся сами | Без правки кода окон: при показе окна (перехват `WM_SHOWWINDOW`) и раз в секунду обходятся подписи кнопок, надписей, вкладок, групп, заголовков, пункты меню, заголовки столбцов, подсказки `ToolTip`. ## 2. Схема

* **Пути:** 1 (главный), 2, 3, 4; тупик за М6 (М6Т); вытяжка за М1 (ВТ). Справа все пути — тупики.
* **Стрелки:** 1, 2, 8 и спаренный съезд **4/6**. «+» = положение `left` из Python, «−» = `right`.
* **Светофоры:** входной **Ч** (Ж З К Ж Б), выходные **Н1–Н4** (Ж З К Б), маневровые **М2** (белый + синий), **М6, М8, М10, М1** (белый + красный — как в Python).
* **Участки:** Ч-М2, 2СП, 4СП, 6-8СП, 1СП, 1П, 2П, 3П, 4П, М6Т, ВТ и два блок-участка перегона: НАУ (у поста) и Б12 (перед Ч).
* **Однопутный перегон к посту** — слева, как в окне поста программы АКЖТ: светофор НА поста (имитация), проходные **1** (к посту) и **2** (к Алгабасу), смена направления (обычная и вспомогательная). Проходной неправильного направления погашен.

## 3. Маршруты — 24

| Вид | Маршруты | Показание |
|---|---|---|
| Приём | Ч → путь 1 / 2 / 3 / 4 | путь 1 — один жёлтый (прямо, дальше тупик); 2, 3, 4 — два жёлтых (по отклонению) |
| Отправление | Н1 / Н2 / Н3 / Н4 → перегон на пост (1) | Н1 — зелёный или жёлтый (по проходному 1); Н2–Н4 — жёлтый (по отклонению, второго жёлтого на выходных нет) |
| Маневровые → | М2 → пути 1–4, М6 → пути 2/4, М8 → вытяжка, М10 → вытяжка | белый |
| Маневровые ← | М1 → путь 1/3, Н1–Н4 → М2, Н2/Н4 → тупик М6 | белый |

Приём возможен только при направлении «→», отправление — только при «←». Пока задан хоть один поездной маршрут, направление сменить нельзя.

Из Python **не перенесены**: «Ч → М1» (поездной маршрут в вытяжной тупик — так не бывает) и длинные маневровые «М2 → М1», «М1 → М2» через весь путь 1 (на станции их делают двумя маршрутами: М2 → путь 1, потом М8 → вытяжка).

## 4. Вся логика как у АКЖТ

Враждебность, замыкание, перевод стрелок с контролем, перекрытие светофора при вступлении поезда, посекционное размыкание, искусственная разделка (поездная и маневровая — отдельно), правило блок-схемы (занятость НЕ первого участка при открытом светофоре → маршрут разбирается), «поезд принят», пригласительный на Ч, вспомогательный перевод стрелки, упрощённый вид, журнал, подсказки по показаниям.

Имитация: «Поезд от поста» (появляется на НАУ, только при направлении «→»), галочка «Пост принимает (светофор НА поста открыт)», «Соседи принимают автоматически», постановка поезда на любой путь, тупик или вытяжку.

Маневровый состав, приехавший к М2 (на Ч-М2), на перегон не выезжает — туда только поездом по маршруту отправления.

## 5. Arduino (`Algabas/AlgabasHardware.cs`)

Прошивка — **та же StationMain**, что уже стоит в Arduino Алгабаса. Её **не трогаем**.

* **Лампы** — 34 штуки, 5 байт, ровно как `HW_MAP_40` в Python. Проходной 2 перегона (в Python `ALB_Sect1-2_2`) — тоже на этой плате (биты 3.7, 4.0, 4.1).
* **Стрелки:** 1 → канал 1, 2 → канал 2, 8 → канал 8, 4/6 → каналы 4 **и** 6 (как в Python). `W <канал> 1` = плюс, `2` = минус.
* **Датчики** (строка `Data:` от платы 74HC165, '0' = занято), биты как в Python `SEGMENT_ORDER`:

| Бит | Участок | В Python |
|---|---|---|
| 0 | М6Т | ("M6", "beforeM6") |
| 1 | Ч-М2 | ("M2", "Ч") |
| 3 | 1П | ("M8", "H1") |
| 4 | 3П | ("M10", "H3") — в Python этот участок записан и в бит 2, но бит 4 его сразу перезаписывает, поэтому реально работает бит 4 |
| 5 | 1СП | ("M8mid", "M8") |
| 6 | 2СП | ("M2", "M2H1_mid") |
| 7 | НАУ | ("ALB_Sect1", "ALB_Sect1-2") — **проверить**: я считаю, что это блок-участок перегона у поста |
| 8 | 6-8СП | ("M6H2", "M6") |

Если Arduino больше 3 секунд не присылает `Data:`, занятость от датчиков снимается (не «залипает»), в журнале красная запись. Вверху окна строка «Датчики: …» показывает, что сейчас занято по датчикам.

## 6. Связь с программой АКЖТ

Связи нет (так решили). Пост на экране Алгабаса имитируется. В программе АКЖТ проходные 1/2 этого перегона в `Post/PostHardware.cs` стоят на временных битах платы АКЖТ — на макете проходной 2 подключён к плате Алгабаса, поэтому лампами на макете управляет программа Алгабаса.

## 7. Как проверено

* Проект собирается без ошибок.
* Автотест логики — все проверки пройдены:
  * **каждый** из 24 маршрутов: задаётся, открывает свой светофор, подсветка совпадает с участками, поезд проходит, участки размыкаются за ним;
  * показания Ч (один жёлтый / два жёлтых), проходного 2 (жёлтый / зелёный / жёлтый мигающий), проходного 1 погашен при «→»;
  * полный цикл: поезд от поста → путь 3 → «поезд принят» → смена направления → Н3 → перегон → уход на пост;
  * враждебность, манёвры на занятый путь, манёвры не выезжают на перегон, пригласительный на Ч;
  * карта проводов: 34 лампы в 5 байтах, нет двух ламп на одном бите, у каждого станционного светофора распаяны все лампы, у всех стрелок есть сервопривод, разбор строки `Data:`.
* **На макете не проверено** (нет доступа к железу).

## 8. Как запустить

1. Откройте `Algabas.sln` в Visual Studio, F5.
2. Вверху слева выберите COM-порт Arduino Алгабаса.
3. Чтобы собрать один файл для флешки — дважды щёлкните `build_exe.bat`, результат в папке `ГОТОВАЯ_ПРОГРАММА`.
