# PromServer — сервер связи диспетчеров АКЖТ ↔ Алгабас

**1.4 (20.10.2026):** к серверу подключается и программа «Преподаватель» (имя станции `teacher`); сообщения до 4 МБ (снимки экрана станций, результаты занятий). Протокол занятия — `Core/Training.cs` программ станций. Обычно сервер запускает сама программа «Преподаватель».

Промежуточный сервер на Go. Программы двух пультов (АКЖТ + путевой пост, Алгабас)
подключаются к нему по WebSocket. Каждая присылает показания светофоров, которыми
управляет сама, а сервер пересылает их другой станции.

По ТЗ:
* **АКЖТ** управляет светофорами **НА** и **1** перегона «пост — Алгабас», **Алгабас** их только показывает.
* **Алгабас** управляет светофорами **Ч** и **2**, **АКЖТ** их только показывает.

Кроме светофоров, у станций общий **однопутный перегон**:
* **направление** — сменить его можно только с согласия дежурного соседней станции (см. «Смена направления» ниже);
* **занятость участков НАУ и Б12** — каждая станция видит и свою занятость, и занятость соседа
  (в списке участков пометка «(сосед)»);
* **маршрут на перегон** — поездной маршрут отправления на перегон («Ч → перегон на Алгабас», «Н1–Н4 → перегон на пост»)
  подсвечивает жёлтым весь перегон (НАУ, Б12) до входного светофора соседа — и у себя, и у соседа;
* **поезда** — поезд, ушедший с перегона на соседнюю станцию, появляется у неё на том же участке с тем же номером
  и едет дальше по её светофорам.

Сервер про конкретные светофоры и перегоны ничего не знает: какие светофоры чьи, решают программы станций.
Поэтому без изменений в сервере можно добавлять светофоры и третью станцию.

## Запуск

1. Двойной щелчок по `PromServer.exe` на любом ПК в сети, который включён, пока идёт занятие.
2. Windows спросит разрешение для брандмауэра: разрешить в **частных сетях**.
3. В окне сервера будет написан адрес, например `ws://192.168.8.8:8090/ws`. Этот адрес вписывается в обе программы станций.
4. Состояние связи можно смотреть в браузере по адресу `http://192.168.8.8:8090/`: какие станции на связи и какие показания они прислали. Страница обновляется каждые 2 с.

Параметры:

| Параметр | Что делает |
|---|---|
| `-addr :9000` | другой порт (по умолчанию `:8090`) |
| `-v` | писать в окно каждое изменение показаний |

Остановить сервер: Ctrl+C или закрыть окно.

Пересобрать exe: `build_exe.bat` (нужен Go 1.23+). Он сначала прогоняет автотесты.

## Подключение программ станций

В программе АКЖТ и в программе Алгабаса вверху, рядом с портом Arduino:
1. Нажмите **«Связь…»**, впишите адрес сервера (достаточно `192.168.8.8`, порт и `/ws` подставятся сами), нажмите **«Подключить»**.
2. Индикатор рядом с кнопкой:
   * серый «Связь: выключена» — работает как раньше, сосед имитируется галочками;
   * красный «нет сервера» или «сервер есть, Алгабаса/АКЖТ нет» — светофоры соседа показываются **красными**;
   * зелёный «Алгабас на связи» / «АКЖТ на связи» — светофоры соседа показывают то, что у соседа.
   * красный «…на связи, направление НЕ совпадает» — направления перегона разошлись, у нас задан маршрут на перегон
     (направление соседа примется, как только маршрут разберут).
3. Адрес запоминается, при следующем запуске программа подключается сама. Если сервер выключили, программа
   переподключается каждые 3 с.

### Смена направления перегона

* Дежурный нажимает «Сменить направление». Программа проверяет свои условия и отправляет запрос соседу.
  Сосед проверяет свои условия: нет маршрутов на перегон, перегон у него свободен. Если они не выполнены, сразу
  приходит отказ с причиной, например «станция Алгабас — задан маршрут Н1 → перегон на пост (1)».
* Если условия выполнены, у дежурного соседа открывается окно **«Смена направления»**: откуда и куда, кнопки
  **«Дать согласие»** и **«Отказать»**, обратный отсчёт. Окно открывается поверх всех окон, на том мониторе, где мышь.
  Согласие — направление меняется у обеих станций. Отказ или нет ответа ~57 с — у запросившего в журнале
  «ОТКАЗ … дежурный отказал» / «не ответил».
* Пока ждём ответа (до 60 с, рядом с направлением видно «согласование: N с»), маршруты на перегон не задаются
  ни у одной из станций.
* Вспомогательная смена: сосед даёт согласие, выдержку ведёт тот, кто начал. У соседа на это время маршруты на
  перегон заблокированы, а направление он принимает, когда выдержка закончится.
* Связь выключена — направление меняется только у себя, как раньше. Соседа нет на связи — тоже только у себя,
  при его подключении направления сверятся.
* Сверка: у направления каждой станции есть версия, она растёт при каждой смене. Если направления разошлись,
  берётся более новое (при равных версиях — направление АКЖТ). Если у станции задан маршрут на перегон, чужое
  направление она примет только после его разборки.

Если сервер не находится:
* сервер запущен и его окно открыто;
* оба ПК в одной сети (адрес из окна сервера открывается в браузере второго ПК);
* брандмауэр Windows на ПК сервера пропускает PromServer (частные сети).

## Протокол

WebSocket, адрес `ws://<ПК>:8090/ws`. Одно сообщение = один JSON-объект в UTF-8.

### Станция → сервер

```json
{"type":"hello","station":"akzht","name":"АКЖТ + путевой пост"}
```
Первое сообщение, его надо прислать в течение 10 с после подключения. `station` — латиницей (`a-z`, цифры, `-`, `_`).
Договорённые имена: `akzht` и `algabas`.

```json
{"type":"signals","signals":{"НА":"TwoYellow","1-ОП":"Dark"},"lines":{"ОП":{"dir":"Left","ver":4}},
 "sections":{"НАУ":true,"Б12":false}}
```
**Полный** снимок состояния станции (не добавка к прошлому снимку): показания светофоров, которыми она
управляет, направление общих перегонов (`dir`: `Right` — к Алгабасу, `Left` — к посту; `ver` — версия, растёт при каждой смене)
и занятость общих участков так, как её видит сама станция (поезда, датчики, вручную — без занятости, присланной соседом).

Любые **другие поля** снимка сервер (с версии 1.3) не разбирает, а пересылает соседям в `state` как есть. Сейчас так
идёт `"routes":{"НАУ":"train","Б12":"train"}` — общие участки, по которым у станции задан поездной маршрут на перегон.
Новые данные между программами можно добавлять без новой версии сервера. Имя поля — латиницей, не больше 16 полей.
Присылать при изменении. Повтор того же снимка безвреден: сервер его не пересылает.
Значения — имена `Aspect` из C#-ядра: `Dark, Red, Yellow, YellowBlink, Green, TwoYellow, TwoYellowTopBlink, Invite, White, Blue`.

```json
{"type":"event","to":"algabas","data":{"kind":"dir_request","line":"ОП","dir":"Left","aux":false,"ver":5,"id":1,"timeout":60}}
{"type":"event","to":"akzht","data":{"kind":"dir_reply","id":1,"ok":false,"reason":"дежурный отказал"}}
{"type":"event","to":"algabas","data":{"kind":"dir_cancel","id":1}}
{"type":"event","to":"algabas","data":{"kind":"train","section":"Б12","dir":"Right","number":2}}
```
Разовое сообщение другой станции. Сервер `data` не разбирает и не запоминает, только пересылает адресату как
`{"type":"event","from":"akzht","data":{...}}`. Если адресата нет на связи, сервер отвечает `error`.
Программы используют его для:
* `dir_request` / `dir_reply` — запрос смены направления и ответ дежурного;
* `dir_cancel` — запросивший больше не ждёт (вышло время), окно у соседа закрывается;
* `train` — поезд ушёл на соседнюю станцию с общего участка `section`, у соседа он появляется там же.

```json
{"type":"ping"}
```
Проверка связи, сервер сразу отвечает `{"type":"pong"}`. Программы станций шлют `ping` каждые 5 с.
Если 15 с от сервера ничего не приходит, связь считается потерянной и программа переподключается.

### Сервер → станция

```json
{"type":"welcome","station":"akzht","server":"PromServer 1.3"}
```
Ответ на `hello`.

```json
{"type":"state","station":"algabas","name":"Станция Алгабас","online":true,
 "signals":{"Ч":"Yellow","2-ОП":"Green"},"lines":{"ОП":{"dir":"Left","ver":4}},"sections":{"НАУ":false,"Б12":true},"updated":"2026-10-12T10:39:17+05:00"}
```
Состояние **другой** станции. Приходит:
* сразу после `welcome` — по каждой станции, о которой сервер знает;
* когда другая станция подключилась (сначала с пустыми `signals`, `lines`, `sections`) или прислала новое состояние;
* когда другая станция отключилась: `online:false`, пустые `signals`, `lines`, `sections`.
  Её показания больше не действительны, светофоры соседа надо показывать закрытыми.

```json
{"type":"error","message":"..."}
```
Ошибка в сообщении. Связь при этом не рвётся, кроме ошибки в `hello`.

### Контроль связи

* Сервер шлёт WebSocket-ping каждые 10 с. Если от станции 30 с нет ни pong, ни сообщений, связь считается потерянной.
  `ClientWebSocket` в .NET отвечает на ping сам, пока идёт чтение (`ReceiveAsync`).
* Если станция подключилась заново, а старое соединение ещё не закрыто (обрыв сети), сервер закрывает старое.
  Другая станция при этом не получает ложного «нет связи».

## Файлы

| Файл | Что в нём |
|---|---|
| `main.go` | запуск, адреса для программ, страница состояния `/` и `/status` (JSON) |
| `hub.go` | кто подключён, последнее состояние станций, рассылка, пересылка `event` |
| `client.go` | одно подключение: приём, отправка, ping, проверки |
| `protocol.go` | описание сообщений |
| `server_test.go` | автотесты: пересылка, направления, занятость, `event`, отключение, переподключение, ошибки |
