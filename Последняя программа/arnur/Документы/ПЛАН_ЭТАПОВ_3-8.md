## 0. Как работать с заказчиком

- Заказчики — **программисты, не железнодорожники**. Правила ЖД решай сам «как на реальной станции / как в тренажёре из PDF», не переспрашивай очевидное.
- Работаем **по этапам**. Каждый этап: собран, проверен, лежит в `arnur\готовая_программа`, записан в `CHANGES.md`. В конце этапа спрашиваем, начинать ли следующий.
- **Экономь токены**: не пиши длинных отчётов, не перечитывай большие файлы целиком без нужды.
- Язык общения, интерфейса и комментариев в коде — русский. Позже понадобятся казахский и английский (этап 8).
- Казахстанских образцов бланков и журналов нет, поэтому берём формы ДУ из PDF (РЖД).
- Класс: ~3 ПК студентов + ПК (или ноутбук) преподавателя, Windows 11. Программы должны работать **и с макетом (Arduino), и без него**. На макете есть физический поезд, но виртуальные поезда тоже нужны.

### Сборка

- Каждый проект: свой `build_exe.bat`. Собирает один self-contained exe (win-x64) сразу в `arnur\готовая_программа\<Папка>`.
- Всё сразу: `arnur\собрать_всё.bat`. bat с параметром (`build_exe.bat x`) не ставит паузу в конце.
- Нужны .NET SDK 8 (установлен 8.0.425) и Go 1.23+.
- Для быстрой проверки компиляции: `dotnet build <csproj> -v q -nologo`.
- **bat-файлы должны быть в CRLF и UTF-8.** С LF и кириллицей cmd ломается. Генерируй их Python-скриптом с `newline='\r\n'`. Не пиши их через heredoc: там портятся `\\`.
- Пользовательские файлы рядом с exe (`scheme_style.ini`, `датчики.txt`, папка `Arduino`) не затирать: publish их не трогает.

## 3. Этап 3 — неисправности (экспресс-вводные), ДУ-46, кнопки со счётчиком

Образец: инструкция преподавателя, раздел 2 (`pdf_files\4@…`), часть 2, разделы 1, 12, 13 (`pdf_files\2@…`).

### 3.1 Что задаёт преподаватель

В программе «Преподаватель» на вкладке «Занятие» — кнопка «Неисправность…» для выбранной станции. Плюс, по желанию, ПКМ по объекту на картинке экрана станции.

Окно «Экспресс-вводная»:
1. **Объект**: список светофоров, стрелок, участков и перегонов станции. Станция присылает его по запросу `t_objects` → `s_objects {signals:[{id,label}], switches:[…], sections:[…], lines:[…], trains:[…]}`.
2. **Тип неисправности** (ответ Д1: «эти вполне хватят»):
   - светофор: не открывается; самопроизвольное перекрытие;
   - стрелка: не переводится в «+»; не переводится в «−»; потеря контроля; отжим 4 мм; не переводится из «+»; не переводится из «−»;
   - рельсовая цепь: ложная занятость; ложная свободность;
   - автоблокировка (перегон): невозможность смены направления; ложная свободность перегона;
   - поезд (подвижная единица): неисправность двигателя (стоит); неисправность тормозов; негабарит; сход.
   - УКСПС **не делаем**: на макете его нет.
3. **Условие возникновения** (ответ Д2: «как в примере, по сложному»):
   - объект: состояние сейчас / «состояние X» / «переход в состояние X» / «переход из состояния X». Для светофора: открыт, закрыт. Для стрелки: +, −. Для участка: свободен, занят, назначен (= замкнут в маршруте);
   - дополнительно для поезда: любой / номер / тип (поездной, маневровый, грузовой, пассажирский — после этапа 4) / скорость, длина, вес — что будет у модели.
4. **Начало ожидания условия**: «немедленно» или с заданного **игрового** времени.
5. Кнопки «Принять» / «Отказ» и список заданных неисправностей станции. Неисправность можно удалить вручную (ответ Д4: «оба варианта»).

Протокол: `t_fault_add {fault}`, `t_fault_remove {id}`; станция отвечает `s_faults {list}` с состоянием: ждёт условия / действует / устраняется / устранена.

### 3.2 Как неисправность работает на станции

Новый общий файл `Core/Faults.cs`, оба режима (ответ Д3: имитация и управление макетом):

| Неисправность | Режим имитации (поведение модели) | На макете |
|---|---|---|
| Светофор не открывается | `ComputeAspects`: светофор остаётся закрытым, маршрут задан | лампы горят, как в модели |
| Самопроизвольное перекрытие | открытый светофор закрывается, маршрут остаётся замкнутым | то же |
| Стрелка не переводится в «+»/«−» | `ToggleSwitch` / `StartMove`: перевод начат, контроль не приходит, стрелка без контроля (мигает) | команда `W` на сервопривод **не уходит** |
| Потеря контроля / отжим 4 мм | `Controlled = false` без перевода; светофоры по маршруту закрываются | — |
| Ложная занятость | новое поле `FaultOcc` у участка входит в `Occupied` (отдельно от `ManualOcc`) | датчик игнорируется, участок занят |
| Ложная свободность | участок не занимается от поезда или датчика; опасно — нужен контроль | данные датчика игнорируются |
| Перегон: нельзя сменить направление | `DirectionBlocker` возвращает причину | — |
| Поезд: двигатель / тормоза | виртуальный поезд встаёт / не может остановиться у сигнала (проезд → критическое событие) | на физический поезд не влияет, только сообщение |
| Сход | поезд стоит, участок занят; нужен восстановительный поезд (этап 7) — пока только сообщение и занятость | — |

- Вне занятия неисправности не задаются: только через преподавателя.
- Пока неисправность действует, студент видит обычную картину пульта, без надписей «неисправность»: он должен сам понять, что случилось.

### 3.3 Журнал осмотра ДУ-46 и устранение (студент)

Новое окно станции «Журнал осмотра ДУ-46». Открывается ПКМ по объекту → «Неисправность…» и кнопкой в полосе занятия.

1. Студент пишет запись о неисправности («Текст записи» → «Занести в журнал»). У записи: игровое время, станция, ФИО студента.
2. Сообщает причастным: список ДНЦ, ШЧ/ШН (электромеханик), ЭЧ, ПЧ, начальник станции → «Сообщить». Время сообщения пишется в «Порядок действий».
3. «Виртуальный ШН» по таймеру (игровое время, 2–5 мин) присылает **сообщение** (только «Закрыть») и **доклад** («Подписать» / «Закрыть»). Подписанный доклад об устранении снимает неисправность.
4. Преподаватель может снять неисправность вручную (Д4).
5. Оценка: неисправность не записана в ДУ-46 до устранения или не сообщено ШН и ДНЦ → неправильное действие (−5). Пригласительный, ИР и ВК без записи в ДУ-46 → −5. Записи ДУ-46 попадают в `s_result`, и в подробном отчёте добавляется раздел «Журнал ДУ-46» (как в PDF: «все записи из журнала ДУ-46 по каждой возникшей неисправности»).

### 3.4 Кнопки со счётчиком (Е3)

- Пригласительный, ИР (искусственная разделка), ВК (вспомогательный перевод) — у каждой свой счётчик на пульте: число на кнопке или рядом.
- Нажатие → счётчик +1 → окно записи в ДУ-46 («нажата кнопка …, показание счётчика N»), как рис. 10 части 2.
- Счётчики хранятся между запусками в `%LOCALAPPDATA%\Station…\counters.txt` и обнуляются в начале урока.

### 3.5 Готово, когда

- Преподаватель задал каждую неисправность из списка, она сработала по условию (проверить «переход участка в занят»). Студент устранил её через ДУ-46 / ШН, преподаватель снял её вручную. Режим макета не шлёт `W` на неисправную стрелку.
- Отчёт содержит ДУ-46 и штрафы. Тест `tools\e2e_teacher_test.ps1` расширен сообщениями `t_fault_*`.
- Обновлены `CHANGES.md` (АКЖТ 5.2, Алгабас 2.3), `КАК_ПРОВЕСТИ_ЗАНЯТИЕ.txt`, всё собрано в `готовая_программа`.

## 4. Этап 4 — журналы, бланки, поезда, радиосвязь, предупреждения

Образец: часть 1, разделы 1.5, 1.8, 1.11; часть 2, разделы 2, 17–24.

### 4.1 Поезд как объект (Ж1)

- У `VirtualTrain` появляются номер (ввод вручную, по чётности направления: чётный / нечётный), индекс, категория (пассажирский, грузовой, хозяйственный, локомотив, маневровый), длинносоставный, тяжеловесный, негабаритный, длина в условных вагонах.
- ПКМ по поезду → «Номер и индекс…» (окно как рис. 13 части 1).
- Для физического поезда на макете: «поезд» = занятость участков по датчикам. Номер можно присвоить на участке; храним его по участку и передаём дальше при занятии соседнего участка.

### 4.2 Поездная радиосвязь (Ж2)

ПКМ по поезду → «Вызвать по радиосвязи». Окно «Поезд №…», команды:
- **Указание** (регистрируемый приказ на проследование запрещающего сигнала): поезд один раз проезжает ближайший закрытый светофор. Приказ записывается в журнал. Проезд без приказа → критическое событие «проезд запрещающего сигнала».
- **Остановка**, **Осаживание** (назад до следующего участка), **Сократить стоянку** (после этапа 5), **Предупреждение** (ограничение скорости: виртуальный поезд едет медленнее).
- Для физического поезда — только запись в журнал.

### 4.3 Журналы (студент заполняет сам — З1)

Общий механизм `JournalWindow`: таблица + форма справа, «Добавить», редактирование, **удалять нельзя**. Все журналы уходят в `s_result`, преподаватель видит их в подробном отчёте.

| Журнал | Поля (по образцу ДУ) |
|---|---|
| ДУ-2 / ДУ-3 — движение поездов | № поезда, индекс, путь приёма, прибытие (ч:мин), отправление, проследование, примечания «ПС» / «ПР» |
| ДУ-47 — поездные телефонограммы | №, время, кому, текст, подпись |
| ДУ-58 — диспетчерские распоряжения | № приказа, время, текст (заготовки приказов слева, как рис. 61) |
| ДУ-60 — предупреждения | №, место (км / путь / перегон), скорость, с какого / до какого времени, отмена |

Автопроверка (З7: «давай и оставь для препода»): программа сравнивает ДУ-2 с фактом (поезд принят на путь X в ЧЧ:ММ ± 2 мин; номер). Расхождения → неправильные действия −2 и отметка в отчёте. Окончательно решает преподаватель.

### 4.4 Бланки (З6: «что посчитаешь нужным» — делаем все из PDF)

ДУ-50 (путевая записка), ДУ-52 (ПАБ), ДУ-54 (АБ), ДУ-55/56, ДУ-61, ДУ-64. Окно «Бланки…» → создать → заполнить → «Вручить машинисту» (выбор поезда).
- **ДУ-54 / ДУ-50, врученный поезду**, разрешает ему проследовать закрытый выходной светофор: виртуальный поезд едет. Без бланка или приказа это критическое событие.
- Остальные бланки хранятся и попадают в отчёт.
- Поля бланков — как на рисунках части 2. Картинки в PDF плохие, поэтому поля бери из стандартных форм ДУ.

### 4.5 Предупреждения и «окна» (Ж6)

ПКМ по участку или перегону → «Установить предупреждение…» (км с … по …, скорость для пасс. / груз. / всех, до времени или до отмены). Отдельно — «окно» (закрытие пути). Предупреждение на конкретный поезд — через радиосвязь.
- На схеме участок с предупреждением подчёркнут (пунктир), «окно» — перечёркнут. В «окно» маршрут не задаётся.
- Виртуальные поезда на таком участке едут медленнее (шаг `StepSeconds` × коэффициент).

### 4.6 Готово, когда

Все окна открываются на станции и через удалённое управление преподавателя (клавиатура работает через SendKeys). Журналы и бланки есть в подробном отчёте. Автопроверка ДУ-2 работает. Сквозной тест расширен.

## 5. Этап 5 — расписание, поезда по расписанию, ГИД

Образец: часть 1, раздел 1.6 и раздел II (ГИД), пульт «Енисей», раздел VI (расписание).

- **Учебное расписание** (Ж3: «придумай учебный»): `Teacher\данные\schedule.json`, у урока — ссылка на расписание. Поезд: номер, категория, откуда (подход: тоннель, пост, Алгабас), прибытие, стоянка, отправление, путь приёма по ТРА.
  - Составь 2–3 учебных расписания на 1 игровой час для пары АКЖТ ↔ пост ↔ Алгабас: грузовые, пассажирские со стоянкой, пропуск без остановки, встречные на однопутке.
- **Поезда сами появляются по расписанию** (Ж4: «по расписанию и по кнопке») у входного светофора с номером. Кнопки имитации остаются.
  - Источник поезда — та станция, где его подход. Поезд, ушедший на соседа, уже переходит сам (DispatchMirror).
  - Опоздание отправления больше 5 мин против расписания → критическое событие «опоздание».
- **Окно «Расписание»** на станции: таблица (№, приб., отпр., стоянка, путь), сортировка по столбцам, фильтр по категориям, печать.
- **ГИД** (Ж5: «нужно»): у преподавателя отдельная вкладка «ГИД».
  - Ось времени (игровое) × станции (АКЖТ — пост — Алгабас). Нитки поездов строятся из событий прибытия, отправления и проследования, которые станции шлют сообщением `s_train_event`. Пунктиром — нормативный график из расписания.
  - Режимы: нормативный график, ГИД, ГИД на нормативном. Наведение на нитку → номер, индекс. Масштаб и прокрутка мышью и клавишами.
  - Картинка ГИД — в подробный отчёт (PNG через `Control.DrawToBitmap` или SVG в HTML).
  - Расчёт участковой и технической скорости (как в PDF, «показатели работы») — в отчёт. Длины перегонов задать в настройках условно.

## 6. Этап 6 — функции пульта ДСП (блок Е)

Всё ниже — «да» заказчика. Выдержки настраиваются у преподавателя (вкладка «Уроки» или «Настройки») и передаются в `t_session`.

| № | Функция | Как |
|---|---|---|
| Е1 | Отмена маршрута с выдержкой | Свободный предмаршрутный участок — 6 с. Занятый: поездной 3 мин, маневровый 1 мин. Индикаторы «ОС» / «ОП» / «ОМ» горят красным, пока идёт выдержка. Сейчас отмена мгновенная или через ИР 15/5 с — переделать |
| Е2 | Искусственная разделка 3–4 мин | Настраивается (сейчас 15 с / 5 с в имитации). Кнопка «ИР» + выбор неразомкнувшихся секций, счётчик (этап 3) |
| Е4 | Замыкание стрелок | Кнопки «Чёт. зам. стрелок», «Нечёт. зам. стрелок», «ЗС» (вся станция), фиксируемые: ЛКМ — включить, ПКМ — выключить. Красная подсветка, счётчик + ДУ-46 |
| Е5 | Красные колпачки | ПКМ по стрелке → «Установить / удалить красный колпачок». Стрелка не переводится с пульта, на схеме метка |
| Е6 | Курбель | ПКМ по стрелке: «Опустить / поднять курбельную заслонку», «Перевести курбелем в +/−» (только при опущенной заслонке; выдержка, сообщение работника «ОК»), «Запереть на закладку и замок», «Закрепить на типовую скобу», снять |
| Е7 | Выключение стрелки из централизации с сохранением сигналов + «макет» | ПКМ → «Выключение из централизации» (доклад ШН «Подписать» / «Закрыть») → стрелка без контроля → «Установить на макет» (выбор положения) → «Информация» (реальное положение) → «Снять макет» → «Включить в централизацию» |
| Е8 | Автодействие | Кнопки «АДЧ» / «АДН»: при заданном сквозном маршруте по главному пути светофоры открываются сами после проследования поезда. ПКМ — выключить. Срыв пломбы → запись в ДУ-46 |
| Е9 | Ключ-жезл | Лампа «Ключ-жезл» перегона: изъять (мигает), выдать локомотиву, забрать, вложить. Пока ключ изъят: на перегон по сигналу — одна единица, смена направления запрещена. Хозяйственный поезд с возвращением |
| Е10 | Переезд | Кнопки «Извещение на переезд», «Отмена извещения», «Закрытие переезда», лампа ЗП (белая — свободен, мигает — закрывается, красная — закрыт). При открытом переезде маршруты с занятого пути через переезд не задаются. Сейчас у поста одна кнопка «Закрыть / Открыть переезд» (`LevelCrossing.ManualClosed`) — расширить |
| Е11 | Взрез стрелки | Виртуальный поезд вступает на стрелку, стоящую не по его ходу (с пошёрстного направления) → взрез: лампа «Взрез» красная, звонок, стрелка без контроля. Кнопка «Отключение звонка взреза». Критическое событие. Восстановление — через ШН (этап 3) |
| Е12 | Звуки | Звонки взреза, уведомления, окно согласия. УКСПС нет. `System.Media.SoundPlayer` или сгенерированный WAV |
| Е13 | Контроль положения стрелок | Кнопка или зажатие обеих кнопок мыши: на схеме подсвечиваются положения всех стрелок (+ зелёным, − жёлтым) |
| Е14 | Раздельное управление (как «Енисей») | Режим урока: стрелки маршрутом не переводятся. ДСП сам ставит стрелки, потом нажимает светофор начала — светофор открывается, если стрелки стоят по маршруту и всё свободно |

Готово, когда каждая функция есть на обеих станциях, видна преподавателю, использование попадает в журнал действий, а ошибки — в оценку.
