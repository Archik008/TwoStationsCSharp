2. Құрастыру

  • Қажет: .NET SDK 8 немесе жаңасы (SDK 10 net8 құрастырады), сервер үшін — Go 1.23+.
  • Әр жобада өз build_exe.bat файлы бар: бір файлды self-contained exe (win-x64) бірден готовая_программа\<бума> ішіне. Параметрмен (build_exe.bat x) — соңында кідіріссіз.
  • Бәрін бірден: собрать_всё.bat (Go болмаса сервер құрастырылмайды — қалғандарын бір-бірден құрастырыңыз).
  • Компиляцияны жылдам тексеру: dotnet build Station.csproj -v q -nologo.
  • exe жанындағы пайдаланушы файлдарын (scheme_style.ini, датчики.txt, Arduino) құрастыру қайта жазбайды.
  • bat файлдары CRLF және UTF-8 болуы керек (LF және кирилл әріптерімен cmd бұзылады).

5. Желі және сабақ хаттамасы

PromServer бір реттік хабарламаларды {"type":"event","to":…,"data":{…}} (4 МБ дейін) data ішін талдамай таратады. Станциялар мен оқытушы (station = "teacher") — клиенттер. Сабақ хаттамасы — data.kind өрісі, толық тізім Core/Training.cs басында:

Оқытушы → станцияСтанция → оқытушы
t_hello, t_login, t_session (сабақ, студент, уақыт, тіл, кесте), t_time, t_take, t_stop, t_screen (терезе аймағы), t_input, t_objects, t_fault_add, t_fault_remove, t_lang s_hello, s_login, s_register, s_progress, s_screen, s_objects, s_faults, s_train_event (ГИД), s_result (оқиғалар, әрекеттер журналы, ақаулықтар, ДУ-46, пойыздар, docs — журналдар мен бланкілер кестелері, supplied / removed / localDeparted)

Станциялар арасында: DispatchMirror — аралықтың ортақ учаскелерінің бос еместігі, көрші бағдаршамдары, бағытты ауыстыруға келісім, пойызды беру (kind = "train" нөмірімен және паспортымен: санат, индекс, натуралық парақ).

Жаңа хабарламаларды сол схема бойынша қосыңыз (t_* / s_*); қабылдау: станцияда — Training.OnEvent, оқытушыда — Classroom.OnEvent.

6. Оқытушы бағдарламасы

  • Data.cs — студенттер (құпиясөз хеші), сабақтар (Lesson — PropertyGrid редакторы; Wire өрісі станцияларға кетеді), нәтижелер (GameResult, DocTable), баптаулар, Db (exe жанындағы данные бумасы).
  • Classroom.cs — станциялар, кіру, сабақ, уақыт, сервер. TeacherForm.cs — қойындылар. Reports.cs — HTML есептер және CSV ведомость. StationScreenWindow.cs, ScreenView.cs — станция экраны. FaultDialog.cs — экспресс-кіріспелер. ScheduleTab.cs, Gid.cs, GidTab.cs — кесте және ГИД.
  • Сабақтың жаңа қасиеті: Lesson ішінде (санат, жазу) + Wire ішінде + LessonTask ішінде де дәл солай (Core/Training.cs).

7. Макет және Arduino

ДК → Arduino, бағдаршамдар: 'L' + N байт (1 бит = 1 шам, 0 = ЖАНАДЫ)
ДК → Arduino, бағыттамалар:  "W <арна> <1|2>\n"   1 = плюс, 2 = минус, PCA9685 арнасы
Arduino → ДК, датчиктер:     "Data: 1011…\n"  (74HC165, '0' = учаске БОС ЕМЕС)
Arduino → ДК, датчиктер:     "Occ: 101\n"     (АКЖТ: датчиктер тікелей пиндерде)
  • Алгабас: шамдар мен бағыттамалар картасы — Algabas/AlgabasHardware.cs. 22.10.2026 бастап бағыттамалар шилдтің 0–4 ажыратқыштарында (1 → 0, 4/6 → 1 және 2, 8 → 3, 2 → 4); калибрлеу — готовая_программа\Алгабас\Arduino\StationMain\Switches.h скетчінде. Датчиктер — exe жанындағы датчики.txt (учаске = бит нөмірі).
  • АКЖТ: микробағдарлама готовая_программа\АКЖТ\Arduino\StationMain_AKZHT, түсініктемелер — сол жердегі ИНСТРУКЦИЯ.txt; ескі микробағдарламаның сақтық көшірмесі — Backup. Скетчті баптаушылар 27.10.2026 Алгабас скетчі үлгісімен жасаған; серво арналары — AkzhtHardware.cs, Post/PostHardware.cs, калибровка — Switches.h. Платамен алмасу exe жанындағы arduino_diag.log файлына жазылады.
  • АКЖТ: бағдаршам шамдарының картасы — pin кестесі бойынша (Документы), «АКЖТ + аралық» нұсқасы, 13 байт; AkzhtHardware.cs ішінде және exe жанындағы светофоры.txt файлына шығарылады («АКЖТ Н5 жёлтый = 0.6», «ПОСТ 1-I красный = 7.3»), қайта құрастырусыз түзетіледі. StationMain_AKZHT микробағдарламасы (LIGHT_FRAME_BYTES = 13). Сымдарды тексеру — «Шамдар бір-бірден» батырмасы (Ui/LampTestForm.cs).
  • Core/ArduinoLink.cs бағдарламаларда әртүрлі — көшірмеңіз.
  • Тақтасыз бәрі жұмыс істейді: бағыттамалар тек экранда ауысады, пойыздар — виртуалды.

8. Аударма

Кодтағы жолдар орысша қалады — олар кілттер. Аударма көрсету кезінде жасалады: терезелер, мәзірлер, MessageBox, кестелер өздері аударылады (Ui/LangUi.cs); өз салуыңыз — L.T(мәтін), формат — L.F("…{0}…", …), HTML — L.Html. Деректер мен хаттамада — тек орысша.

  1. Интерфейсті орысша, жақсысы тұтас үлгілермен жазыңыз ($"Поезд №{n} на {s}", бөліктерден жапсырмай).
  2. python Инструменты\i18n\check.py --todo новое.tsv — аудармасыз жаңа жолдар.
  3. Қазақша мен ағылшынша жазып, Инструменты\i18n\strings.tsv ішіне көшіріңіз (керексіздерін — skip.txt ішіне).
  4. python Инструменты\i18n\check.py --build → Lang\Strings.kk.json / en.json сөздіктері екі станцияға → қайта құрастыру.

Қазақша теміржол терминдерін тіл иесі тексеруі керек: Инструменты\i18n\ПРОВЕРИТЬ_КАЗАХСКИЙ.md.

10. Түзету ережелері

  • Түзетуге түсініктеме — // [ДОБАВЛЕНО күні, этап N] немесе [ИЗМЕНЕНО …]; түсініктемелер мен интерфейс — орысша.
  • Ортақ файлдар екі станцияда бірдей (түзетуден кейін — cp және cmp).
  • Файлдардың жол соңдары мен кодтамасын өзгертпеңіз (түзетпес бұрын CRLF / LF қараңыз).
  • Әр нұсқа — екі станцияның CHANGES.md файлына жазба: «Не / Қалай / Файлдар» кестесі, «Тексерілді» және «Тексерілмеді».
  • Бұрынғы кезеңдердің тесттерін бұзбаңыз; жаңа функциялар — өз тестімен.

11. Тексерілмегені және келесі қадамдар

  • Тікелей тексерілмеген: барлық терезелердегі шертулер, бірнеше ДК арасындағы жұмыс, нақты датчиктер мен пойыз нөмірлері бар макет, дыбыс, АКЖТ-ның екі мониторы.
  • Қазақша терминдер — тіл иесінің тексеруі.
  • Тапсырыс беруші кейінге қалдырды: пойыз диспетчерінің (ДНЦ) бағдарламасы.
